# A股每日观点与事实复盘

产出一份有来源、时间和版本的日报：上一交易日判断 → 今日市场事实 → 判断验证 → 博主观点变化 → 下一交易日观察条件。由当前助手分析转录；不把标题当作原话，不把多数观点当作事实，不自动执行交易。

## 输入与来源池

默认时区 `Asia/Shanghai`。先确认目标交易日、盘前/盘中/收盘阶段和数据截止时间。日期按交易所日历核实；周末、节假日不能按自然日递减推算“昨天”。未指定时分析当前日期；尚未收盘则输出阶段性报告，判定保持 pending。

每天早上08:00的定时复盘采用晨间模式：设执行日为R，D为R之前最近一个已收盘交易日，P为D的上一交易日。分析D的视频与收盘行情，用D的实际结果验证P记录中针对D的判断，再保存D的日报及针对D下一交易日的观察条件。例如周二早上复盘周一，用周一大盘验证上周五的事前判断。每位作者先获取最近6期，按P收盘后至D当天23:59:59筛选相关内容，转录实际入选的视频；页数不足时补采并披露抽样范围。

晨间模式的`trading_date`为D、`cutoff_at`为D的23:59:59（+08:00），真实保存时间由服务写入。R凌晨到08:00的新视频单列“今日盘前补充”，不得混入D的市场事实或回改P预测；可用`save_analysis`另存补充，相关判断只有满足其证据截止时间和日期规则时才能建档。若D已完成复盘且无新相关证据，返回既有版本和新增内容摘要，不重复增加验证样本或虚构休市行情。首次运行缺P记录时明确首次建档。

使用 [references/default-watchlist.json](references/default-watchlist.json) 的已解析作者建立或读取 `a-share-daily` 固定清单。用户提供的主页/频道优先；昵称不能代替UID。更完整的发现池位于项目 [公开博主总表](../../html/skills/creator-catalog.md)。个人关注关系只可用于本地个性化，不写入公开名单、网页或报告。候选的日更、粉丝数、身份、原创性必须重新核实；非财经账号、未解析主页、纯课程与未授权转载不默认监控。用户要求全池时分批处理并报告覆盖，不默默截断。

同一讲者的大小号或转载号归到一个来源组；共识按独立来源组计数。粉丝数仅作来源描述，不作为预测权重。按指数/ETF、题材/短线、宏观、基本面分层展示，不把美股/港股/黄金的结论混成A股大盘结论。

## 执行

1. 调用 `get_system_status`。读取 `get_daily_research` 的已存日期与上一交易日记录，保留 revision；没有记录就明确“首次建档”，不能依据今日结果重建昨天预测。
2. 用 `manage_creator_watchlist` 读取清单；不存在时按默认JSON创建。更新时先读旧清单，合并用户新增项，不覆盖其他作者。`research_creator_watchlist(refresh=true)` 获取更新。该工具直接返回结果；若改用 `get_latest_videos` 且作者超过三人，会返回job_id，要用 `get_job(wait_seconds=30)` 取齐条目。保留逐作者错误与完整性。
3. 按截止时间、交易日窗口和视频ID去重。保留昨天收盘后至今天收盘期间的新视频；明确盘前观点、盘中修正、盘后解释。已转录的视频复用缓存，没更新不算采集失败。默认每人最多两条用于启动，若同一天更多视频或关键观点在更早视频，补采并注明采样缺口；不能声称初始两条覆盖整天。
4. 将完整视频元数据提交 `batch_transcribe`，轮询终态，收集成功的artifact ID。`analyze_videos(model="host")` 只是准备分析；再用 `read_artifact` 分页读完正文。重要判断保留来源URL、发布日期、转录时间戳、条件和期限。需要核对图表/字幕时才下载并 `extract_video_frames`，不批量下载无关内容。
5. 独立查询当日大盘事实和交易日历。优先交易所、指数公司、官方公告；汇总行情可用明确口径的行情提供方。每个数值记录source_url、observed_at、unit。至少尝试沪指/深成指/创业板/沪深300涨跌幅和收盘点位、两市成交额、涨跌家数、涨停跌停、领涨领跌行业。无法取得的数据记缺失，不补猜。来源冲突说明市场范围、单位和时间；北向数据若不可得或口径改变不制造“实时净流入”。
6. 用 `evaluate_daily_forecasts` 对照昨日记录与今日market，逐条解释结果。自动判定只用于已有阈值/单位/期限的规则；条件句、模糊方向、因果理由用人工证据核查，不能强行二元化。保留所有命中、未命中、不可判定、未触发、数据缺失和未到期，不只挑成功案例。
7. 按 [assets/daily-report.md](assets/daily-report.md) 写日报；读 [references/evidence-and-scoring.md](references/evidence-and-scoring.md) 处理数据字段、工具调用和判定限制。区分博主原话、助手解释与外部事实。对比昨日原始判断和今日变更时保留两条证据，说明时间与依据。
8. 将报告、market、覆盖状态、缺口和下一交易日 forecasts 传给 `save_daily_research`，获得revision。数值规则只能来自原话明确表达或事前约定的统一口径；不得事后设置阈值让结果命中。未读到转录就不生成该博主预测。模糊/条件判断也保留，设置scorable=false并写原因。大盘事实日报可没有转录，但必须说明“博主分析未完成”，不能伪装完整报告。

## 归档与输出

每日记录保存在MCP的 `Paths.root/daily-research/YYYY-MM-DD/`，每次修订生成独立JSON和Markdown；`latest`仅是查询指针。今日开盘后的修订不能成为昨日预测基线。工具返回baseline_revision时报告必须注明该版本，而不是拿昨日latest替换。

返回日报文件路径、目标交易日/截止时间、覆盖作者和视频数、市场资料来源、缺失项、可判定样本数和下一交易日观察条件。第一天无历史预测则建立基线；下一次运行再评估。只有真实样本才汇总命中率，并同时给样本数/未判定数；不把命中率换算成收益率。

本Skill按调用执行，不能宣称已经自动定时。用户明确要求定时运行时通过宿主调度机制配置，之后报告排程状态。对外发布默认使用报告摘要和原视频链接；不发布Cookie、账号资料或原始视频/全文转录，也不把示例展示为真实验证结果。
